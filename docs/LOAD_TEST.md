# 壓力測試（k6）使用說明

**目的**：在多位同仁同時使用前，先量出網站在多少人同時在線時開始變慢，並留下測試紀錄（可作為系統上線前驗證的佐證）。

- 腳本：`tests/load/teacher-load.js`
- 自動化：`.github/workflows/load-test.yml`（**只能手動執行**）

## 它會做什麼、不會做什麼

| 會做 | 不會做 |
|---|---|
| 模擬同仁進站：開登入頁、載入 JS／CSS、查詢登入狀態 | 不上傳教材、不產生 AI 內容、不作答考試（這些會寫入資料或消耗 AI 額度） |
| 若有提供帳號：登入**一次**後，由所有虛擬使用者共用，再讀取首頁、儀表板、課程、公告、我的指派、我的進度（學員平常開首頁會讀到的內容） | 不會讓每個虛擬使用者各自登入，所以不會觸發登入失敗鎖定 |
| 全程只用「讀取」（GET），唯一的 POST 是登入一次 | 不會在正式站新增、修改或刪除任何資料 |

## 怎麼執行（在 GitHub 網頁上操作）

1. 開啟專案 GitHub 頁面 → 上方 **Actions**。
2. 左側清單點 **Load test (manual)**。
3. 右側點 **Run workflow**（灰色按鈕）。
4. 選 **profile**（測試強度，見下表），其他欄位通常不用改。
5. 點綠色 **Run workflow**，等 2～6 分鐘。
6. 重新整理後點進最新那一筆，頁面下方的 **Summary** 會顯示中文結果；完整報告在最下方 **Artifacts**。

| profile | 意義 | 時間 | 建議用途 |
|---|---|---|---|
| `smoke` | 1 人 | 約 30 秒 | 先確認腳本與網站都正常 |
| `staff10` | 約 10 人同時 | 約 3 分鐘 | 平常上班時段的情境 |
| `peak30` | 約 30 人同時 | 約 5 分鐘 | 上線初期多人同時登入的情境 |

**建議順序**：`smoke` → `staff10` → `peak30`。

### 對正式站執行的注意事項

- `staff10`、`peak30` 對正式站執行時，必須勾選 **confirm_production**，否則會被擋下。
- 請選**非上班時段**（例如晚上），避免測試期間影響同仁實際使用。
- 正式站目前使用 Render 免費方案，閒置後會休眠；工作流程會先「喚醒」網站（可能需要等幾分鐘）再開始量測，所以第一次喚醒的時間不會算進結果。
- 免費方案資源有限，**測到 ❌ 是預期中會發生的事**，這正是要事先知道的資訊。

## 怎麼看結果

結果範例：

```
一般頁面：中位數 120 ms，95% 在 800 ms 內，最慢 2100 ms ✅
API       ：中位數 90 ms，95% 在 600 ms 內，最慢 1500 ms ✅
結論：✅ 在這個強度下，網站表現符合標準。
```

- **95% 在 X ms 內**：代表 100 次操作中有 95 次比這個時間快。這比平均值更能反映使用者實際感受。
- **通過標準**：失敗率低於 2%；一般頁面 95% 在 3 秒內；API 95% 在 2 秒內。
- 看到 ❌：代表該強度下已超過標準。請記下「最多同時幾人」是通過的，並把這個數字當作目前的使用上限參考。

## 讓測試更貼近實際使用（選用）

### 1. 使用壓力測試帳號登入

工作流程使用的帳號順序：

1. `TEACHER_LOAD_USERNAME` / `TEACHER_LOAD_PASSWORD`（**建議**：另外建立一個權限最低的學員帳號專供壓力測試）
2. 沒有時，沿用既有監控帳號 `TEACHER_SMOKE_USERNAME` / `TEACHER_SMOKE_PASSWORD`
3. 兩者都沒有時，只測試未登入就能看到的頁面

新增專用帳號的方式：

1. 在網站上建立一個學員帳號（例如命名為「壓力測試」，不要用真人帳號）。
2. GitHub 專案 → **Settings** → **Secrets and variables** → **Actions** → **Secrets** 分頁。
3. 點 **New repository secret**，Name 填 `TEACHER_LOAD_USERNAME`，Secret 填帳號，存檔。
4. 再新增一個 `TEACHER_LOAD_PASSWORD`，填密碼，存檔。

> 帳號讀不到的資料路徑會被自動略過，並寫在測試紀錄裡，不會讓整個測試誤判失敗。

### 2. 加入更多要測的「讀取」頁面

1. GitHub 專案 → **Settings** → **Secrets and variables** → **Actions** → **Variables** 分頁。
2. 點 **New repository variable**。
3. Name 填 `LOAD_TEST_EXTRA_PATHS`。
4. Value 填要測的唯讀網址，用逗號分隔，例如：`/api/learning-progress,/api/learning-assignments`。
5. 存檔後重新執行測試。

> 只能放「讀取」用的路徑。會新增、修改資料的功能不要放進來。

## 在自己電腦執行（進階，選用）

需先安裝 k6，再執行（`<網址>` 請換成要測的網站）：

```
k6 run -e BASE_URL=<網址> -e PROFILE=smoke tests/load/teacher-load.js
```

可用的 `PROFILE`：`smoke`、`staff10`、`peak30`、`stress60`。`stress60`（約 60 人）用來找極限，**只建議對自己電腦或測試站使用，不要對正式站執行**。

本機測得的速度不能代表正式站（兩者硬體不同），本機只用來確認腳本正常。

## 作為上線驗證紀錄

每次執行都會在該次 Actions 紀錄保留報告（保留 14 天）。若評鑑或內部稽核需要留存，請將結果頁的 Summary 截圖或下載 Artifacts 後，與當次版本號（`VERSION` 檔）一併歸檔。
